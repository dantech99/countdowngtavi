# Internacionalización es/en — diseño

Fecha: 2026-08-31
Estado: aprobado en brainstorm, pendiente de plan de implementación

## Objetivo

Servir el sitio en español e inglés, con un switch manual para cambiar de idioma y
detección automática del idioma del navegador en la primera visita.

## Restricciones del proyecto

Verificadas en el repositorio antes de diseñar:

- El sitio es **100 % prerenderizado**. La única ruta bajo demanda es `/api/waitlist`
  (`export const prerender = false`). Por lo tanto `Astro.preferredLocale` y el middleware
  nativo de i18n de Astro **no están disponibles**: solo corren en rutas renderizadas bajo
  demanda. La detección tiene que resolverse en el cliente.
- `site` no está configurado en `astro.config.mjs`. Los `hreflang` y el `canonical` exigen
  URLs absolutas, así que hay que configurarlo.
- Tres puntos tienen el formato casado con español y hay que parametrizarlos:
  `toLocaleDateString('es', …)` en `NewsCard.astro` y en `noticias/[slug].astro`, y
  `Intl.NumberFormat('es-CO')` más el plural de `formatCount()` en `src/lib/waitlist.js`.
- `Layout.astro` carga AdSense y `@vercel/analytics/astro`. Ambos se preservan sin cambios.
- El último commit sacó una prop de `Layout.astro` a propósito. El diseño evita
  reintroducir props en el Layout.

## Decisiones

| # | Decisión | Alternativa descartada y por qué |
|---|---|---|
| 1 | Español sin prefijo, inglés bajo `/en/` | `/es/` + `/en/` simétricos: rompía todas las URLs ya indexadas y obligaba a redirects 301 |
| 2 | Artículos separados por idioma, feeds RSS compartidos | Fallback al español: mezcla idiomas en la misma página |
| 3 | Detección solo en la primera visita a `/` | Detección en cualquier página: secuestra links compartidos |
| 4 | Switch en un header fijo nuevo | Footer: invisible en la home hasta pasar el hero a pantalla completa |

## 1. Rutas

```js
// astro.config.mjs
site: 'https://countdowngtavi.com',
i18n: {
  defaultLocale: 'es',
  locales: ['es', 'en'],
  routing: { prefixDefaultLocale: false },
},
```

El bloque `i18n` declara los locales ante el framework. **La generación de rutas es manual**,
vía un rest param opcional, y la derivación del idioma usa un helper propio con test
(`getLangFromUrl`), no `Astro.currentLocale`. Un solo camino de código, cubierto por tests,
sin depender de cómo interactúa la i18n nativa de Astro con rutas de rest param.

```
src/pages/
  [...locale]/index.astro             -> /          y  /en/
  [...locale]/noticias/index.astro    -> /noticias   y  /en/noticias
  [...locale]/noticias/[slug].astro   -> /noticias/:slug y /en/noticias/:slug
  404.astro                           -> /404
  api/waitlist.ts                     -> sin cambios
```

Cada página resuelve `getStaticPaths()` devolviendo `{ params: { locale: undefined } }` y
`{ params: { locale: 'en' } }`. Con `locale: undefined` el rest param desaparece de la URL.
Esto mantiene **un archivo por página** en vez de doce, que es donde la duplicación se
convierte en divergencia.

Para `[...locale]/noticias/[slug].astro`, cada artículo pertenece a exactamente un idioma,
así que los paths salen de la colección: `locale` es `undefined` para los de `es/` y `'en'`
para los de `en/`.

**Excepción, el 404.** Astro solo reconoce `src/pages/404.astro` en la raíz para el 404
estático, y Vercel sirve ese único `404.html` para cualquier ruta inexistente, incluidas las
de `/en/`. Se hace **bilingüe**: el texto en los dos idiomas y un botón `Inicio / Home`. Una
página que por definición no sabe de dónde vino no puede detectar idioma de forma confiable.

Las URLs actuales (`/`, `/noticias`, `/noticias/bienvenida`) no cambian. Cero redirects.

## 2. Traducciones de UI

```
src/i18n/
  ui.ts          diccionario, única fuente de verdad
  utils.js       getLangFromUrl, useTranslations, localizePath, switchLangPath
  utils.test.js
```

```ts
export const DEFAULT_LANG = 'es';
export const LANGS = ['es', 'en'] as const;
export type Lang = (typeof LANGS)[number];

export const ui = {
  es: { 'hero.title': 'Cuenta regresiva a GTA VI', /* … */ },
  en: { 'hero.title': 'GTA VI Countdown',          /* … */ },
} as const satisfies Record<Lang, Record<string, string>>;
```

El `satisfies` hace que **una clave faltante en inglés sea un error de tipos**, no un
`undefined` que llega a producción. `astro check` ya está en el proyecto y lo detecta.

### Strings en scripts de cliente

Cuatro componentes tienen texto dentro de `<script>`, no en el frontmatter, y un `<script>`
de Astro no puede importar del frontmatter. Se pasan por atributos `data-*` en el elemento
sobre el que ya opera el script:

```astro
<button id="waitlist-button"
  data-label-idle={t('waitlist.cta')}
  data-label-sending={t('waitlist.sending')}
  data-label-joined={t('waitlist.joined')}
  data-label-error={t('waitlist.error')}>
```

Afecta a `Waitlist.astro` (estados del botón y mensaje de error), `MusicToggle.astro`
(`aria-label` y el texto `sr-only`), `NewsCard.astro` y `noticias/[slug].astro` (locale de
fecha), y `src/lib/waitlist.js` (`formatCount(n, lang)`).

## 3. Contenido bilingüe

```
src/content/articulos/
  _assets/portada.jpg     compartida entre idiomas
  es/bienvenida.md
  en/welcome.md
```

El loader actual (`glob({ pattern: '**/*.md', base: './src/content/articulos' })`) ya recorre
subdirectorios sin modificarlo: `entry.id` pasa de `bienvenida` a `es/bienvenida`. El patrón
`**/*.md` no toca imágenes, así que `_assets/` queda fuera de la colección y se referencia
desde cada `.md` como `../_assets/portada.jpg`: una sola copia del binario en vez de una por
idioma.

**El idioma se deriva del directorio, no del frontmatter.** Un campo `lang: en` en un archivo
que vive en `es/` puede mentir; la ruta no. Helpers puros en `src/lib/articulos.js`:

```js
articleLang('es/bienvenida')  // 'es'
articleSlug('es/bienvenida')  // 'bienvenida'
```

Un `.md` fuera de un directorio de idioma conocido **lanza en build** con un mensaje claro.
Un artículo que no se publica y no avisa es peor fallo que un build roto.

**Emparejar traducciones.** Se agrega `translationKey: z.string().optional()` al schema, con
default al propio slug. Dos archivos con el mismo slug se emparejan solos sin escribir nada;
`translationKey` solo hace falta cuando el slug difiere, que es lo que permite
`/en/noticias/welcome` en vez de `/en/noticias/bienvenida`.

Filtrado en las páginas: `getCollection('articulos', ({ id }) => articleLang(id) === lang)`.
`mergeNews()` no cambia: recibe la lista ya filtrada y los feeds compartidos.

Los feeds (GameSpot, Eurogamer, VG247) son en inglés y se muestran igual en ambos idiomas,
como ya ocurre hoy en el sitio en español.

`src/content/articulos/en/welcome.md` se escribe como traducción de `bienvenida.md`, con
`translationKey: bienvenida`.

## 4. Header, switch y detección

### Header

`src/components/Header.astro`, renderizado en `Layout.astro` junto a `Footer` y
`MusicToggle`. **Sin props.**

Contenido: nombre `GTA 6 COUNTDOWN` como link a la home del idioma actual, link a
`Noticias`/`News`, y el switch.

Comportamiento visual: **transparente en scroll 0, sólido al bajar**
(`bg-black/70 backdrop-blur border-b border-white/10` después de ~80 px). En la home el hero
se ve íntegro; en `/noticias` un header transparente sobre un `body` que ya es `bg-black` es
visualmente idéntico a uno sólido. Por eso no hace falta ninguna prop que distinga las
páginas, y no hay flash de hidratación.

Estilo reusado de `MusicToggle`: `border-white/20`, `bg-black/70`, `backdrop-blur`,
`hover:border-gta-pink`. La transición usa GSAP `ScrollTrigger`, ya presente y ya usado así
en `Hero.astro`.

`/noticias` y `/noticias/[slug]` usan `py-16` (64 px), que no alcanza para despejar un header
fijo de ~56 px. Pasan a `pt-24 pb-16` (96 px arriba). La home no necesita ajuste: el hero es
`h-screen` y el header va deliberadamente encima.

### Switch

Segmentado `ES | EN` con el idioma activo resaltado: comunica el estado y cambiar es un solo
tap.

**Son `<a href>` reales, no botones.** Funcionan sin JavaScript, Google los rastrea, y el
`href` es el mismo valor que va en el `hreflang`, de modo que hay una sola fuente de verdad.

El `click` escribe `localStorage['gta6:lang']` y deja seguir la navegación. Con JS apagado el
link igual funciona, solo no se recuerda. Se usa el mismo `try/catch` que ya emplean
`MusicToggle` y `Waitlist` para el modo privado.

`switchLangPath(pathname, targetLang, articleIndex)`, función pura:

| Estás en | Apunta a |
|---|---|
| `/` | `/en/` |
| `/noticias` | `/en/noticias` |
| `/en/noticias` | `/noticias` |
| `/noticias/bienvenida` | `/en/noticias/welcome` |
| artículo sin traducir | `/en/noticias` |

El caso del artículo necesita los pares de traducción. El Header los obtiene **leyendo la
colección él mismo** (`getCollection('articulos')`) y construyendo el índice de
`translationKey`. Es costo de build, la colección ya está cacheada por Astro, y mantiene la
lógica en un solo lugar en vez de arrastrarla como prop por el Layout.

### Detección

Script inline en el `<head>`, **solo en la home en español**:

```astro
{Astro.url.pathname === '/' && (
  <script is:inline>
    try {
      if (!localStorage.getItem('gta6:lang') &&
          navigator.language.toLowerCase().startsWith('en')) {
        location.replace('/en/');
      }
    } catch {}
  </script>
)}
```

- `is:inline` y en el `<head>`: corre síncrono antes del primer paint, así que no hay flash
  de contenido en español.
- `location.replace` en vez de `href`: no ensucia el historial, el botón "atrás" no queda
  atrapado.
- `try/catch`: el modo privado puede lanzar al tocar `localStorage`.
- **No escribe nada.** Solo el switch escribe. Eso lo hace idempotente: cada visita a `/` sin
  preferencia guardada vuelve a detectar, que es el comportamiento acordado.
- Googlebot no lo ejecuta y no manda un `navigator.language` de navegador, así que indexa `/`
  como español y `/en/` como inglés.

Consecuencia aceptada: alguien con navegador en inglés que prefiera el sitio en español
rebota a `/en/` al entrar a la raíz. Se corrige con un click en el switch y queda guardado.

## 5. SEO

En `Layout.astro`, todo derivado de `Astro.url`, sin props nuevas:

```astro
<html lang={lang}>
  <link rel="canonical" href={canonicalUrl} />
  <link rel="alternate" hreflang="es" href={esUrl} />
  <link rel="alternate" hreflang="en" href={enUrl} />
  <link rel="alternate" hreflang="x-default" href={esUrl} />
```

- `<html lang>` hoy está fijo en `"es"`; pasa a ser dinámico. Es lo que usan los lectores de
  pantalla para elegir la voz.
- `x-default` apunta al español porque `/` es la entrada canónica.
- `canonical` no existe hoy y con dos idiomas hace falta: sin él `/` y `/en/` compiten por la
  misma consulta.

**El `hreflang` y el switch siguen reglas distintas** para el mismo caso:

| | Artículo con traducción | Artículo sin traducción |
|---|---|---|
| Switch | va al artículo equivalente | va a `/en/noticias` |
| `hreflang` | declara la contraparte | **no emite nada** |

El `hreflang` no puede caer al índice como hace el switch: declarar que `/en/noticias` es la
traducción de `/noticias/bienvenida` es falso y Google lo descarta. El switch prioriza que el
usuario no choque con un 404; el `hreflang` prioriza no mentir.

**El 404 no emite `canonical` ni `hreflang`.** Es una sola página bilingüe que responde a
cualquier URL inexistente, así que no tiene una URL canónica propia ni una contraparte que
declarar. El Layout los omite cuando la página es el 404.
